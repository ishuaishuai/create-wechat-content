# 公众号创作工作流（公开版 v1.0）

## 遵守四条边界

1. 把配置保存在用户选择的文件夹，不假设任何私人路径。
2. 默认只生成本地文件；不自动设置定时，不自动调用平台接口。
3. 只有用户明确授权时才推入平台草稿；只有真实成功回执才能登记完成。
4. 绝不代替用户发表或群发，不把凭证写进配置、文章或日志。

## 首次启动：九题一次问清

1. 检查用户指定文件夹中是否已有 `creator-profile.resolved.json`。
2. 没有配置时，读取 `references/onboarding.md`，一次给出 9 个问题及默认值。
3. 用户已提供答案时直接采用，不重复提问；允许用户粘贴 `assets/公众号创作启动清单_填写版.md`。
4. 只补问会影响安全或无法执行的关键信息。无关紧要的缺项使用默认值。
5. 按 `assets/creator-profile-template.json` 保存配置；不要保存密码、令牌或平台密钥。
6. 九题答完后直接继续创作，不再询问“是否开始”。

已有配置时，读取配置并只询问本次需要变更的字段。用户说“按原来的配置”时，不重新问九题。

## 初始化工作区

使用用户确认的文件夹。相对路径以配置文件所在目录为基准。

```bash
python3 scripts/init_workspace.py --config /path/to/creator-profile.json
```

脚本只创建 `articles/`、`materials/`、`reviews/` 并保存解析后的配置。检查输出；失败时如实报告，不假装已初始化。

## 自动执行创作

读取 `references/workflow.md`，根据请求选择模式：

- **发现选题**：没有具体主题时，研究并给出 3—5 个候选；配置允许时选最优项继续。
- **完整创作**：从主题生成标题、正文、证据、质量报告和本地发布包。
- **改写旧稿**：保留真实信息与个人经历，重构标题、结构、语言和结尾。
- **跨平台改编**：按目标平台重构，不只替换称呼或机械删字。

完整创作对外统一为 7 步：

```text
定主目标 → 诊断选题与证据 → 生成标题池
→ 开头／骨架／正文 → 三道质量检查 → 排版与发布包 → 可选的草稿推送
```

这 7 步是读者友好的执行视图。需要维护时，可在元数据中保留更细的子任务状态。

## 研究和生成要求

- 有时效性的信息先使用可用的搜索或浏览工具核验；没有工具时明确限制，不凭记忆冒充最新消息。
- 优先使用用户提供的素材；读不到文件时说明具体路径和错误。
- 生成 5—10 个标题并推荐 TOP1；数字必须真实、自然、能在正文兑现。
- 全稿直出，不留“待补案例”等空位；不知道的个人经历不得编造。
- 写完后读取 `references/quality.md`，完成事实、读者友好与平台安全检查。
- 评分只表示创作准备度，不预测阅读、点击、涨粉或收入。

## 本地发布包

至少保存：

- `article.md`：正文母版。
- `titles.md`：标题池与推荐理由。
- `evidence.md`：来源、日期、口径和不确定性。
- `quality_report.md`：检查结果与人工复核项。
- `publish_package.md`：摘要、作者、平台、图片与人工设置。
- `creation_metadata.json`：配置摘要、标题、状态和交付边界。

按配置可选生成 HTML、封面和流程图。流程、对比、清单类内容优先增加流程图；图片需在目标平台单独上传并检查手机预览。

需要公众号粘贴版时，先写简单 HTML，再运行：

```bash
python3 scripts/html2wechat.py article.html article_微信粘贴版.html --check --md
```

转换后检查正文、图片与样式；不要承诺编辑器一定保留所有效果。

## 自动化与外发闸门

| 行为 | 默认 | 执行条件 |
|---|---|---|
| 研究生成与本地保存 | 允许 | 配置完成后直接执行 |
| 定时任务 | 不创建 | 用户明确要求时间、频率和时区后另行设置 |
| 推入平台草稿 | 不执行 | 用户明确授权，且当前环境已有合法工具与凭证 |
| 发表或群发 | 禁止代办 | 始终由用户在平台后台操作 |

推送前检查是否已有成功回执，避免重复。失败时保留本地成果与错误；不得用本地文件存在冒充远端成功。

## 交付时说明

1. 列出实际生成的文件和可选的草稿回执。
2. 提醒用户复核事实、数字、个人经历与标题。
3. 提醒检查平台预览、原创声明、合集等接口无法代办的设置。
4. 没有执行的动作明确写“未执行”，不把能力写成结果。
